# 배포 및 운영 가이드

## 현재 배포 형태

이 프로젝트는 서버가 없는 정적 웹 앱이다. 핵심 페이지는 `index.html` 한 파일이며, Leaflet 스크립트/스타일과 OpenStreetMap 지도 타일은 외부 네트워크에 의존한다. 로컬 파일로 실행할 경우 일부 브라우저 환경에서 기능이 제한될 수 있으므로, 배포 후 HTTPS 주소에서 실제 확인하는 것을 권장한다.

## GitHub Pages 배포 절차

1. 저장소의 `main` 브랜치 루트에 `index.html`이 존재하는지 확인한다.
2. GitHub 저장소의 **Settings → Pages**를 연다.
3. Build and deployment의 Source를 **GitHub Actions**로 선택한다 (`.github/workflows/pages.yml` 사용; 엔진 테스트 통과 후 배포).
4. `main`에 푸시하거나 Actions에서 워크플로를 수동 실행한다.
5. Pages 배포 워크플로/상태가 완료될 때까지 기다린다.
6. GitHub가 표시한 Pages URL을 열고 아래 점검을 수행한다.

> 실제 배포 URL은 GitHub Pages 설정 후 GitHub가 제공하는 값을 사용한다. 설정하지 않은 URL을 배포 완료 주소로 안내하지 않는다.

## 배포 후 스모크 테스트

- [ ] 앱 페이지가 HTTPS로 열림
- [ ] 콘솔에 치명적인 JavaScript 오류가 없음
- [ ] Leaflet 지도 라이브러리와 지도 타일이 로드됨
- [ ] 일정 대안과 날짜 탭이 동작함
- [ ] 일정 순서/포함 상태 편집 후 새로고침 복원 확인
- [ ] 사용자 장소를 생성하고 브라우저 저장 후 재실행해 복원
- [ ] 사진 추가 후 브라우저 재실행 시 사진 복원
- [ ] 모바일 뷰포트에서 주요 조작 수행
- [ ] 운영시간·예약·주차가 실시간 보장되지 않는다는 점이 명확함

## 업데이트 절차

1. 변경 전 최신 `main` 상태와 이슈를 확인한다.
2. 명세서의 관련 요구사항과 인수 테스트를 함께 갱신한다.
3. 앱 코드를 수정하고 정적 구문 검사와 브라우저 인수 테스트를 수행한다.
4. 의미 있는 변경 단위로 커밋한다.
5. Pages 배포 상태 및 스모크 테스트를 확인한다.

## 데이터 보관 및 개인정보

- 일정과 사용자 장소 정보는 각 브라우저의 로컬 저장소에 저장된다.
- 사진 파일은 IndexedDB에 저장된다.
- 다른 기기/브라우저로 자동 이동하지 않는다.
- 브라우저 저장 데이터를 삭제하면 일정·장소·사진을 복구하지 못할 수 있다.
- 저장 데이터의 정기 백업 기능은 현재 범위에 포함되지 않는다.

## 문제 해결

### 지도가 표시되지 않음
인터넷 연결, Leaflet CDN 요청, OpenStreetMap 타일 요청 및 콘텐츠 차단 설정을 확인한다. 지도가 없어도 일정 텍스트가 열리는지 확인한다.

### 변경사항이 다시 열 때 사라짐
같은 브라우저/프로필인지 확인하고, 사이트 데이터 저장이 허용되어 있는지 점검한다. 시크릿 모드나 저장소 정책에서는 데이터가 보존되지 않을 수 있다.

### 사진이 보이지 않음
IndexedDB 사용 가능 여부, 이미지 파일 형식/크기, 브라우저 저장 공간을 확인한다.

### 운영정보가 잘못됨
앱은 실시간 영업/예약 확인 도구가 아니다. 장소 공식 채널에 연락하여 당일 운영, 휴무, 입장 마감, 예약 필요 여부를 확인하고 사용자 메모를 갱신한다.

## 호스팅 선택: GitHub Pages vs Netlify

| 항목 | GitHub Pages (현재) | Netlify |
|---|---|---|
| 비용 | 공개 저장소는 무료 (이 저장소는 public) | 무료 플랜 있음 (대역폭·빌드 한도) |
| 설정 | 저장소 Settings → Pages → Source: GitHub Actions | 별도 계정 가입 + 저장소 연결 |
| 배포 | `main` 푸시 시 테스트 통과 후 자동 배포 | 푸시 시 자동 배포, **PR별 미리보기 URL** |
| 주소 | `https://<계정>.github.io/jeonju-family-trip/` | `<이름>.netlify.app` (이름 직접 선택) |
| 추가 기능 | 없음 (순수 정적) | 헤더 설정, 폼, 서버리스 함수, 비밀번호 보호(유료) |

**결론: 지금은 GitHub Pages를 유지합니다.** 서버·계정이 없는 정적 앱이고, 저장소·테스트·배포가 한곳에 있어 관리할 곳이 적습니다. 상대 경로만 사용하므로 `/jeonju-family-trip/` 하위 경로에서도 동작합니다. 다음 경우에만 Netlify를 검토하세요: PR 미리보기가 필요할 때, 짧은 주소를 원할 때, 가족 공유 동기화 등 서버 기능(함수/DB)을 추가할 때. 이전은 정적 파일이라 저장소 연결만으로 가능합니다 (`publish` 디렉터리 `.`, 빌드 명령 없음).

## 휴대폰 사용
- **홈 화면에 추가**: Android Chrome은 메뉴 → 「홈 화면에 추가/앱 설치」, iPhone Safari는 공유 → 「홈 화면에 추가」. 설치 후 앱 셸은 오프라인에서도 열립니다 (지도 타일은 인터넷 필요).
- 일정·기록은 **그 기기의 그 브라우저**에만 저장됩니다. 설치된 앱과 브라우저 탭은 저장소가 다를 수 있으므로 한쪽만 사용하세요. 주기적으로 「설정 → 내보내기」로 백업하세요.
- 자동 점검: `node tests/mobile.js` (iPhone 13/SE, Pixel 7 에뮬레이션: 가로 스크롤, 터치 대상 크기, 입력 글자 크기, 오프라인, 매니페스트, 여행 가져오기). **에뮬레이션이며 실기기 검증이 아닙니다.** 배포 후 실제 휴대폰에서 위 스모크 테스트를 직접 수행하세요.
